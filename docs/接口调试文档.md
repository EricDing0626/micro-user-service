# micro-user-service 接口调试文档

> 作者：Eric  
> 服务名称：micro-user-service  
> 默认地址：`http://localhost:8080`  
> 覆盖模块：认证、用户管理、操作日志、基础数据

## 一、通用说明

### 1.1 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或登录已过期 |
| 403 | 无访问权限 / 用户被禁用 |
| 404 | 资源不存在 |
| 500 | 系统错误 |

### 1.2 认证方式

除登录接口外，所有 `/api/**` 接口需在 Header 中携带 token：

```
Authorization: Bearer {token}
```

或使用：

```
token: {token}
```

### 1.3 注意事项

- Token 存储在**服务内存**中，**重启服务后需重新登录**（BUG-003 已知限制）。
- 除登录拦截外，业务接口 HTTP Status 一般为 **200**，以 body 中 `code` 判断业务结果（见 BUG-004 说明）。
- 测试账号：`testadmin` / `123456`（`init.sql` 初始化）。

## 二、认证接口

### 2.1 用户登录

| 项目 | 说明 |
|------|------|
| 请求地址 | `/api/auth/login` |
| 请求方式 | POST |
| 是否需要 token | 否 |

**请求头**

```
Content-Type: application/json
```

**入参（Body JSON）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | String | 是 | 用户名 |
| password | String | 是 | 密码（明文，服务端 MD5 校验） |

**请求示例**

```json
{
  "username": "testadmin",
  "password": "123456"
}
```

**成功响应示例**

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "a1b2c3d4e5f6789...",
    "userId": 1,
    "username": "testadmin"
  }
}
```

**失败响应示例（密码错误）**

```json
{
  "code": 401,
  "message": "用户名或密码错误",
  "data": null
}
```

**失败响应示例（用户被禁用）**

```json
{
  "code": 403,
  "message": "用户已被禁用",
  "data": null
}
```

## 三、用户管理接口

### 3.1 新增用户

| 项目 | 说明 |
|------|------|
| 请求地址 | `/api/users` |
| 请求方式 | POST |
| 是否需要 token | 是 |

**入参（Body JSON）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | String | 是 | 用户名，唯一 |
| password | String | 是 | 密码，6-20 位 |
| email | String | 否 | 邮箱 |
| phone | String | 否 | 手机号 |
| status | Integer | 否 | 0-禁用，1-启用，默认 1 |
| roleIds | List<Long> | 否 | 角色 ID 列表，1=管理员，2=普通用户 |

**请求示例**

```json
{
  "username": "zhangsan",
  "password": "123456",
  "email": "zhangsan@example.com",
  "phone": "13800138000",
  "status": 1,
  "roleIds": [2]
}
```

**成功响应示例**

```json
{
  "code": 200,
  "message": "新增用户成功",
  "data": 6
}
```

**失败响应示例（用户名重复）**

```json
{
  "code": 400,
  "message": "用户名已存在",
  "data": null
}
```

| 项目 | 说明 |

|------|------|------|------|

**请求示例**

```

```

**成功响应示例**

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "id": 1,
      "typeCode": "user_status",
      "dataCode": "0",
      "dataName": "禁用",
      "sort": 1,
      "status": 1,
      "createTime": "2026-06-15T09:49:34",
      "updateTime": "2026-06-15T09:49:34"
    },
    {
      "id": 2,
      "typeCode": "user_status",
      "dataCode": "1",
      "dataName": "启用",
      "sort": 2,
      "status": 1,
      "createTime": "2026-06-15T09:49:34",
      "updateTime": "2026-06-15T09:49:34"
    }
  ]
}
```

**说明：**

- 结果按 `sort` 升序，再按 `id` 升序
- 首次查询走数据库；相同 `typeCode` 第二次查询命中内存缓存（`spring.cache.type: simple`）
- 新增/修改/删除后缓存失效，下次查询重新查库

**种子数据 typeCode 参考（init.sql）**

| typeCode | 说明 |
|----------|------|
| user_status | 用户状态：禁用、启用 |
| role_type | 角色类型：管理员、普通用户 |

## 六、Postman 调试步骤

1. 执行 `sql/init.sql` 初始化数据库
2. 启动 `MicroUserApplication`（**代码变更后需重启**）
3. 导入 `docs/postman/user-api.postman_collection.json`
4. 导入 `docs/postman/local.postman_environment.json`
5. 环境选择 **micro-user-local**
6. 按模块运行对应文件夹：

| 文件夹 | 说明 |
|--------|------|
| 01-认证 | 登录与未授权场景 |
| 02-用户管理-正常流程 | 用户 CRUD |
| 03-边界场景 | 参数校验、404 等 |
| 04-AOP操作日志验证 | 自动写日志验证 |
| 05-基础数据与缓存验证 | 基础数据 CRUD + 缓存 |

7. 每个文件夹内建议先执行 **登录-成功**，再跑其余请求

## 七、常见错误排查

| 现象 | 原因 | 处理 |
|------|------|------|
| HTTP 401 | 未登录或 token 失效 | 重新登录 |
| HTTP 404（Spring 默认 JSON） | 服务未重启，新接口未注册 | 重启应用 |
| code 400 用户名已存在 | 用户名重复（含已逻辑删除用户） | 更换用户名 |
| code 404 用户不存在 | ID 无效或已删除 | 检查 ID |
| code 404 操作日志不存在 | 日志 ID 无效 | 查库确认最新 id |
| code 400 同类型下数据编码已存在 | typeCode + dataCode 重复 | 更换 dataCode |
| code 404 基础数据不存在 | ID 无效或已逻辑删除 | 检查 ID |
| 第 2 次按类型查询仍打印 SQL | 缓存未生效或服务旧版本 | 确认 Commit 8 代码已部署并重启 |
| 登录失败 | testadmin 未初始化或被禁用 | 重新执行 init.sql 或修复 deleted/status |
