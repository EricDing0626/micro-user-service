# 用户管理模块接口调试文档

> 作者：Eric  
> 服务名称：micro-user-service  
> 默认地址：`http://localhost:8080`

## 一、通用说明

### 1.1 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或登录已过期 |
| 403 | 无访问权限 / 用户被禁用 |
| 404 | 资源不存在 |
| 500 | 系统错误 |

### 1.2 认证方式

除登录接口外，所有 `/api/**` 接口需在 Header 中携带 token：

```
Authorization: Bearer {token}
```

或使用：

```
token: {token}
```

### 1.3 注意事项

- Token 存储在**服务内存**中，**重启服务后需重新登录**（BUG-003 已知限制）。
- 除登录拦截外，业务接口 HTTP Status 一般为 **200**，以 body 中 `code` 判断业务结果（见 BUG-004 说明）。
- 测试账号：`testadmin` / `123456`（`init.sql` 初始化）。

## 二、认证接口

### 2.1 用户登录

| 项目 | 说明 |
|------|------|
| 请求地址 | `/api/auth/login` |
| 请求方式 | POST |
| 是否需要 token | 否 |

**请求头**

```
Content-Type: application/json
```

**入参（Body JSON）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | String | 是 | 用户名 |
| password | String | 是 | 密码（明文，服务端 MD5 校验） |

**请求示例**

```json
{
  "username": "testadmin",
  "password": "123456"
}
```

**成功响应示例**

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "a1b2c3d4e5f6789...",
    "userId": 1,
    "username": "testadmin"
  }
}
```

**失败响应示例（密码错误）**

```json
{
  "code": 401,
  "message": "用户名或密码错误",
  "data": null
}
```

**失败响应示例（用户被禁用）**

```json
{
  "code": 403,
  "message": "用户已被禁用",
  "data": null
}
```

## 三、用户管理接口

### 3.1 新增用户

| 项目 | 说明 |
|------|------|
| 请求地址 | `/api/users` |
| 请求方式 | POST |
| 是否需要 token | 是 |

**入参（Body JSON）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | String | 是 | 用户名，唯一 |
| password | String | 是 | 密码，6-20 位 |
| email | String | 否 | 邮箱 |
| phone | String | 否 | 手机号 |
| status | Integer | 否 | 0-禁用，1-启用，默认 1 |
| roleIds | List<Long> | 否 | 角色 ID 列表，1=管理员，2=普通用户 |

**请求示例**

```json
{
  "username": "zhangsan",
  "password": "123456",
  "email": "zhangsan@example.com",
  "phone": "13800138000",
  "status": 1,
  "roleIds": [2]
}
```

**成功响应示例**

```json
{
  "code": 200,
  "message": "新增用户成功",
  "data": 6
}
```

**失败响应示例（用户名重复）**

```json
{
  "code": 400,
  "message": "用户名已存在",
  "data": null
}
```

---

### 3.2 分页查询用户列表

| 项目 | 说明 |
|------|------|
| 请求地址 | `/api/users` |
| 请求方式 | GET |
| 是否需要 token | 是 |

**入参（Query）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 10，最大 100 |
| username | String | 否 | 用户名模糊搜索 |

**请求示例**

```
GET /api/users?pageNum=1&pageSize=10&username=zhang
```

**成功响应示例**

```json
  "message": "操作成功",
  "data": {
    "records": [
      {
        "id": 6,
        "username": "zhangsan",
        "email": "zhangsan@example.com",
        "phone": "13800138000",
        "status": 1,
        "createTime": "2026-06-08T10:00:00",
        "updateTime": "2026-06-08T10:00:00",
        "roles": [
          {
            "id": 2,
            "roleName": "普通用户",
            "roleCode": "USER"
          }
        ]
      }
    ],
    "total": 1,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 1
  }
}
```

### 3.4 修改用户

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|

```json
{
```
```json
  "code": 200,
  "message": "操作成功",
  "data": null
}
```

### 3.6 批量删除用户

| 项目 | 说明 |
|------|------|
| 请求地址 | `/api/users/batch` |
| 请求方式 | DELETE |
| 是否需要 token | 是 |

**入参（Body JSON）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| ids | List<Long> | 是 | 用户 ID 列表，不能为空 |

**请求示例**

```json
{
  "ids": [6, 99998, 99999]
}
```

**成功响应示例（全部成功）**

```json
{
  "code": 200,
  "message": "批量删除成功",
  "data": {
    "successCount": 1,
    "failedCount": 0,
    "successIds": [6],
    "failedIds": []
  }
}
```

**成功响应示例（部分成功）**

```json
{
  "code": 200,
  "message": "部分用户删除成功",
  "data": {
    "successCount": 1,
    "failedCount": 2,
    "successIds": [6],
    "failedIds": [99998, 99999]
  }
}
```

**失败响应示例（全部不存在）**

```json
{
  "code": 404,
  "message": "批量删除失败，用户均不存在",
  "data": {
    "successCount": 0,
    "failedCount": 2,
    "successIds": [],
    "failedIds": [99998, 99999]
  }
}
```

## 四、Postman 调试步骤

1. 执行 `sql/init.sql` 初始化数据库
2. 启动 `MicroUserApplication`
3. 导入 `docs/postman/user-api.postman_collection.json`
4. 导入 `docs/postman/local.postman_environment.json`
5. 运行 **01-认证 → 登录-成功**
6. 依次测试 **02-用户管理-正常流程** 和 **03-边界场景**

## 五、常见错误排查

| 现象 | 原因 | 处理 |
|------|------|------|
| HTTP 401 | 未登录或 token 失效 | 重新登录 |
| code 400 用户名已存在 | 用户名重复（含已逻辑删除用户） | 更换用户名 |
| code 404 用户不存在 | ID 无效或已删除 | 检查 ID |
| 登录失败 | testadmin 未初始化 | 重新执行 init.sql |
