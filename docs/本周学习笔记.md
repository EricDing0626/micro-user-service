# 本周学习笔记：Spring Boot 分层开发与 MyBatis-Plus 使用要点

## 一、Spring Boot 分层架构

### 1. 标准分层结构

```
com.huawei.micro
├── controller   # 控制层：接收 HTTP 请求，参数校验，调用 Service
├── service      # 业务层：核心业务逻辑、事务控制
│   └── impl     # 业务实现类
├── mapper       # 持久层：数据库访问接口
├── entity       # 实体类：与数据库表一一映射
├── vo           # 视图对象：接口入参/出参封装
├── exception    # 异常处理：自定义异常 + 全局处理器
├── common       # 公共类：统一返回 Result、状态码等
├── util         # 工具类：MD5 加密等
└── config       # 配置类：MyBatis-Plus、数据源等
```

### 2. 各层职责

| 层级 | 职责 | 关键注解 |
|------|------|----------|
| Controller | 路由映射、参数校验、返回统一结果 | `@RestController`、`@RequestMapping`、`@Valid` |
| Service | 业务校验、事务管理、调用 Mapper | `@Service`、`@Transactional` |
| Mapper | 数据库 CRUD、自定义 SQL | `@Mapper`（或通过 `@MapperScan` 扫描） |
| Entity | 表字段映射 | `@TableName`、`@TableId`、`@TableField` |

### 3. 请求处理流程

```
客户端 → Controller → Service → Mapper → 数据库
                ↓
         GlobalExceptionHandler（异常统一处理）
                ↓
         Result<T> 统一返回
```

## 二、统一返回与异常处理

### 1. Result<T> 设计要点

- 泛型 `T` 承载业务数据，无数据时 `data` 为 `null`
- 标准状态码：`200` 成功、`400` 参数错误、`401` 未登录、`403` 无权限、`404` 不存在、`500` 失败
- 提供静态工厂方法：`Result.success(data)`、`Result.fail(message)`

### 2. 异常处理策略

- **BusinessException**：业务层主动抛出，携带自定义错误码和消息
- **GlobalExceptionHandler**：`@RestControllerAdvice` 全局捕获
  - `BusinessException` → 返回业务错误码
  - `MethodArgumentNotValidException` → 返回 `@Valid` 校验失败信息
  - `Exception` → 兜底返回 500

## 三、MyBatis-Plus 核心用法

### 1. 基础配置（application.yml）

```yaml
mybatis-plus:
  mapper-locations: classpath:mapper/*.xml
  type-aliases-package: com.huawei.micro.entity
  configuration:
    map-underscore-to-camel-case: true   # 下划线转驼峰
  global-config:
    db-config:
      id-type: auto                     # 主键自增
      logic-delete-field: deleted       # 逻辑删除字段
```

### 2. 实体类注解

```java
@TableName("sys_user")           // 表名
@TableId(type = IdType.AUTO)     // 主键策略
@TableField("username")          // 字段映射
@TableLogic                      // 逻辑删除
```

### 3. Mapper 接口

- 继承 `BaseMapper<T>` 自动获得：`insert`、`deleteById`、`updateById`、`selectById`、`selectList` 等
- 自定义方法在接口中声明，SQL 写在 `resources/mapper/*.xml` 中

### 4. 自定义 SQL 示例

```xml
<!-- 根据用户名查询 -->
<select id="selectUserByUsername" resultMap="UserResultMap">
    SELECT * FROM sys_user WHERE username = #{username} AND deleted = 0
</select>

<!-- 根据用户ID查角色（多表关联） -->
<select id="selectRoleByUserId" resultMap="RoleResultMap">
    SELECT r.* FROM sys_role r
    INNER JOIN sys_user_role ur ON r.id = ur.role_id
    WHERE ur.user_id = #{userId} AND r.deleted = 0
</select>
```

## 四、数据源与事务

### 1. Druid 连接池配置

```yaml
spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    druid:
      initial-size: 5
      max-active: 20
```

### 2. 事务管理

- 启动类加 `@EnableTransactionManagement`
- 写操作方法加 `@Transactional(rollbackFor = Exception.class)`

## 五、接口参数校验

### Controller 层（JSR-303 注解）

```java
@NotBlank(message = "用户名不能为空")
@Size(min = 6, max = 20, message = "密码长度必须在6-20位之间")
```

### Service 层（业务校验）

- 用户名非空、唯一性校验
- 密码长度 6-20 位
- 用户 ID 存在性校验

## 六、RESTful 接口设计

| 操作 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 新增 | POST | `/api/users` | Body 传 JSON |
| 查询 | GET | `/api/users/{id}` | PathVariable |
| 修改 | PUT | `/api/users` | Body 传 JSON（含 id） |
| 删除 | DELETE | `/api/users/{id}` | PathVariable |

## 七、调试与测试建议
